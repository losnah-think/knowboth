# RoleBridge

## 해결하는 문제

구직자는 공고에 나온 직무 이름과 기술 목록만으로 실제로 어떤 일을 해야 하는지, 자신의 경험이 어디까지 통하는지 판단하기 어렵다. 특히 첫 취업과 경력 이직의 기대 수준은 다르고, 경험하지 않은 산업은 검토 대상에서 쉽게 빠진다.

RoleBridge는 회사의 공고를 먼저 역량과 지원 조건으로 나눈다. 이후 사용자의 경험과 원문 근거를 연결하고, 확인된 역량·일부 수행·명시적인 부족·미확인을 구분한다. 결과는 다음에 확인할 질문, 작은 보완 과제, 새로운 도메인 가설, 이력서 표현으로 이어진다.

대상 직무는 서비스 기획, PM, 개발자, Forward Deployed Engineer(FDE), AX다.

## 사용 흐름

1. `/jobs`에서 AX, PM, FDE 같은 직무 키워드를 검색한다. 현재 검색 소스는 사람인 공개 검색이다. URL을 직접 넣는 UI는 제공하지 않는다. 수집된 공고의 원문 링크는 열어볼 수 있다.
2. `/resume`에서 PDF, DOCX, TXT, MD 이력서를 업로드한다. 파일은 브라우저에서 텍스트로 변환되며 서비스 서버에 파일을 저장하지 않는다. 스캔·이미지 PDF 및 HWP는 미지원이다.
3. 필요하면 추출된 본문과 경험을 수정하고 신입/경력 단계를 선택한다.
4. `/results`에서 공고의 요구 역량과 이력서의 근거를 대조한다. 다중 공고는 같은 입력 경험으로 비교한다.
5. 미확인 경험을 답변하고, 보완 과제와 도메인 탐색 실험을 실행한다.
6. 사실에 맞게 이력서 문장을 수정한다. 보고서·프롬프트는 내려받을 수 있다.

## 구현된 기능과 실제 범위

- 직무 키워드 직접 검색, 3단계 페이지 전환과 이전 단계 수정(입력 상태 유지).
- 공개 URL의 HTML/JobPosting JSON-LD 가져오기. 허용 호스트·리디렉션·크기·시간 제한 적용.
- 사람인 검색결과의 공고 목록과 페이지 이동 수집. 한 번에 최대 5페이지, 다음 묶음 이어받기. 사용자 취소 가능.
- 수집 목록과 상세 본문 확보 항목 분리. 본문을 못 읽은 공고는 점수 미산정. 로그인, 접근 제한, 이미지 공고, 동적 본문은 가져오지 못할 수 있다.
- 로컬 기본 분석: 27개 IT 역량 사전과 문장 규칙. 자동 추출의 누락과 문맥 해석 한계를 표시한다.
- 서버 AI 분석 경로: OpenAI Responses API, 서버 비밀 환경변수. API 미연결 시 실제 AI처럼 동작하는 척하지 않고 프롬프트 복사/JSON 결과 가져오기 대안을 제공한다.
- 모델 응답은 Zod 형식과 공고·경험 인용을 검사한다. 역량 점수는 모델이 아닌 프로그램이 계산한다.
- 이력서 제안에 새 수치·알려진 도구/책임 표현이 생기면 제외한다. 이 검사는 문장 전체의 사실성을 보장하지 않으므로 AI 초안으로 표시하고 사용자 확인을 요구한다.
- 비교함과 이력서는 화면의 메모리에만 있으며 새로고침하면 초기화된다. 계정·장기 저장은 이 MVP에 포함하지 않는다.

## 점수

필수 3, 주요 업무 2, 우대 1 가중치를 적용한다. 근거 확인은 1, 일부 확인은 0.5, 보완 필요는 0, 미확인은 계산 제외다.

- 확인한 역량 일치도 = 확인 가능한 항목의 획득 가중치 / 확인 가능한 항목의 총 가중치
- 판정 가능 비율 = 확인 가능한 항목의 총 가중치 / 전체 추출 항목의 총 가중치
- 전체 역량의 하한/상한 = 미확인을 각각 0점/1점으로 가정한 범위
- 확인 가능한 항목이 없으면 일치도는 미산정이다.
- 필수 연차는 별도 조건이며 스킬 점수에 중복 감점하지 않는다.
- 다중 공고 기본 정렬은 전체 가중치 대비 현재 확보된 역량 근거 비율(하한)이다. 합격 확률이나 검증된 채용 순위가 아니다.

## 차별화 가설

이력서 추천 자체는 기존 채용 서비스에도 있다. 차별화는 다음 네 가지를 실제 사용자 검증으로 입증해야 한다.

1. 공고에서 먼저 평가 기준과 경험 확인 질문을 생성한다.
2. 미확인과 실제 부족을 분리해 불필요한 자기 배제를 줄인다.
3. 신입의 프로젝트 근거를 인정하되 경력 공고의 책임 요구를 낮추지 않는다.
4. 해보지 않은 산업에도 전이할 수 있는 경험을 근거와 실험으로 제안한다.

## AI 활용

제품 설계·프롬프트·웹 구현에 Codex를 사용했다. 런타임에서는 모델이 공고와 경험의 문맥을 구조화하고, 애플리케이션이 인용과 출력 형식을 검사하고 점수를 계산한다. 기본 분석은 LLM이 아니라 설명 가능한 사전 기반 규칙이다. API 연결 전에는 자동 AI 분석을 제공한다고 제출 문구에 쓰지 않는다.

프롬프트는 `lib/rolebridge/prompts.ts`, 독립 문서는 `docs/ANALYSIS_PROMPT.md`에 있다.

## 제출용 소개 초안

**프로젝트명:** RoleBridge — 공고에서 발견하는 나의 가능성

**한 줄 소개:** 채용공고가 요구하는 일을 먼저 읽고, 내 경험의 근거와 연결해 지원 가능성부터 보완 계획까지 안내하는 IT 커리어 탐색 도구.

**해결하려는 문제:** 다양한 공고에서 실제로 필요한 역량을 해석하기 어렵고, 이력서에 적지 않은 경험은 부족으로 오인되며, 신입과 경력의 기대 수준이나 낯선 산업으로의 역량 전이가 충분히 반영되지 않는 문제.

**AI 활용 방식:** 공고의 필수·우대·주요 업무를 분리하고 경험을 근거로 대조하는 구조화 프롬프트를 설계했다. 모델이 판정을 반환하면 프로그램이 원문 인용을 검사하고 설명 가능한 점수를 계산한다. 이 결과를 경험 확인 질문·보완 과제·도메인 가설·이력서 초안으로 연결한다. API 연결 전 배포에서는 프롬프트 실행 결과 가져오기와 로컬 기본 분석을 사용할 수 있다.

**사용 기술:** Codex, React, TypeScript, Vinext/Vite, Cloudflare Workers/Sites, OpenAI Responses API 연동 코드, PDF.js, Mammoth, LinkeDOM, Zod.

## 검증 및 알려진 제한

- 분석 경계·점수·인용·URL 검증 테스트를 실행했다.
- 실제 사람인 PM 검색에서 공고 목록과 다음 페이지를 읽었으나, 확인한 상세 공고는 후속 동적 로딩으로 본문 수집에 실패했다. 이 경우 metadata-only 상태로 목록을 유지한다.
- 실제 원티드 개별 공고는 조사 환경에서 HTTP 403이었다. 접근 제한은 우회하지 않는다.
- AI API 키가 제공되지 않아 실제 모델 응답의 품질·지연·비용은 아직 측정하지 못했다.
- 전체 웹 UI/브라우저 파일 업로드 자동 검증은 별도 수행하지 않았다. WebMCP의 지원 검증 컨텍스트가 현재 도구에 없어 등록/실행 검증도 미수행이다.
- 도메인 추천은 사용자 검증 전 가설이다. 실제 채용 적합도나 합격률을 주장하지 않는다.
