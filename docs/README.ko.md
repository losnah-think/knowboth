# KnowBoth

**Know the company. Know yourself.**

[English](../README.md) · [구조와 데이터 흐름](ARCHITECTURE.md) · [기여 안내](../CONTRIBUTING.md)

기업의 사업과 채용공고, 지원자의 경험을 연결해 근거를 확인할 수 있는 지원 준비 보고서를 만듭니다. Wanted AI Championship 2026을 위해 Next.js, React, TypeScript로 구현했습니다.

화면, 가상 예시, 보고서 표시 문구, PDF 다운로드를 한국어와 영어로 제공합니다. 실제 공고 조사는 **원티드 한국 공고**를 대상으로 합니다. 언어를 바꿔도 지원하는 채용 사이트가 늘어나지는 않으며, 공고·경험의 직접 인용은 검증을 위해 원문을 유지합니다.

## 실행

Node.js 22가 필요합니다.

```sh
npm ci
npm run dev
```

[127.0.0.1:3000](http://127.0.0.1:3000)에서 언어를 선택하고 **예시 보고서 보기**를 누르면 API 키 없이 둘러볼 수 있습니다. 예시는 가상 보고서이며 유료 호출을 하지 않습니다.

실제 분석을 실행하려면 `.env.example`을 `.env.local`로 복사하고 `OPENAI_API_KEY`를 설정하세요. `OPENAI_MODEL`은 선택 사항이며 코드 기본값은 `gpt-5.6-luna`입니다. 해당 계정에서 Responses API의 웹 검색과 구조화 출력을 지원하는 모델을 사용할 수 있어야 합니다. 두 변수에 `NEXT_PUBLIC_` 접두사를 붙이지 마세요.

## 주요 기능

- 원티드 공고 URL 또는 공식 공유 링크를 조사하고 공고 내용을 확인합니다.
- PDF·DOCX·TXT·MD를 브라우저에서 읽고 추출한 경험을 직접 수정할 수 있습니다.
- 기업 이해, 채용 배경, 나와 비교, 지원 준비의 네 영역을 출처와 함께 제공합니다.
- 확인된 정보·해석·추가 확인 사항을 구분하며, 합격 확률이나 종합 점수를 만들지 않습니다.
- 원문을 확인한 다른 기업의 공고를 실제 경험 인용과 연결합니다.
- 취소·재시도, 키보드 탐색, 모바일 화면, 최근 분석 기록, PDF 저장을 지원합니다.

새 공고 분석은 공고 조사·기업 조사·보고서 생성의 세 AI 단계를 거치며, 각 단계는 최대 세 번 시도합니다. 다른 공고 추천에는 별도 유료 호출이 발생합니다. 로딩 단계는 작업 순서이며 서버가 전송하는 실시간 진행률은 아닙니다.

## 코드 확인

```sh
npm run check
npm run build
npx playwright install chromium
npm run test:ui
```

`check`는 형식, 린트, 타입 검사, `tests/**/*.test.ts` 자동 탐색 테스트를 실행합니다. 브라우저 테스트는 프로덕션 빌드에서 가상 응답을 사용하므로 API 키와 유료 호출이 필요하지 않습니다. CI도 같은 검사를 실행합니다.

UI, 분석 흐름, 외부 서비스, 데이터 계약과 근거 검증을 역할별 모듈로 분리했습니다. ESLint에서 계층 간 잘못된 의존성을 검사합니다. 자세한 설명은 [ARCHITECTURE.md](ARCHITECTURE.md)를 참고하세요.

## 데이터와 확인 범위

- 원본 이력서 파일은 브라우저에서만 읽습니다. 분석 시 추출한 텍스트가 서버와 OpenAI에 전달됩니다.
- OpenAI 요청에는 `store: false`를 사용하며 앱 데이터베이스는 없습니다. 제공자의 처리·보존 정책은 별도로 적용됩니다.
- 실제 보고서는 브라우저에 최대 10개, 직렬화 문자열 약 200만 자까지 저장됩니다. 경험 인용이 포함될 수 있으며 개별 삭제가 가능합니다. 원본 파일·이력서 전체 입력·공고 확인 서명은 기록에 저장하지 않습니다.
- 파일은 최대 8MB, PDF는 40쪽, 공고·경험 텍스트는 각각 20,000자입니다. 스캔 PDF·이미지·HWP는 지원하지 않습니다.
- 공고 확인 서명은 입력 무결성을 검사하며 사용자 인증이나 요청 제한을 대신하지 않습니다. 계정·할당량·IP별 요청 제한은 아직 없으므로 실제 공개 운영에는 접근·비용 관리가 필요합니다.
- 자동 검사는 구조·출처 참조·정확한 인용을 확인합니다. 실제 기업 주장, 지원 조건, 매출의 의미는 연결된 원문에서 확인해야 합니다.

로컬 검사 통과는 실제 API 호출, 정확도, 배포 완료를 뜻하지 않습니다. 운영 절차와 상세한 기존 한국어 제품 문서는 [영문 README](../README.md#deployment-and-product-notes)에서 연결합니다.
